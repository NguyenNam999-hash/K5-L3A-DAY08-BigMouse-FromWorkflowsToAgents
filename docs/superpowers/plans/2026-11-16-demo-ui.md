# Demo UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A static, offline demo page that shows the four claim-processing shapes, each pipeline's execution for a selected claim and seed, and the benchmark comparison.

**Architecture:** A stdlib Python generator reads claims, committed reports, and local traces, sanitizes and enriches them into `demo/data.js`. Hand-written `demo/index.html`, `demo/styles.css`, and `demo/app.js` render shape tabs, four hand-authored SVG diagrams, a claim table, a result card, an event detail panel, and a compare panel. No server, no Node, no build step.

**Tech Stack:** Python 3.11 standard library, pytest, vanilla HTML/CSS/JS, inline SVG.

**Spec:** `docs/superpowers/specs/2026-11-16-demo-ui-design.md`

## Global Constraints

- Run everything from the repo root except the existing test gates.
- Python 3.11–3.13, standard library only; do not edit `src/requirements.txt`.
- Test commands use `src/.venv/bin/python`; fall back to `python3` when that venv is absent.
- Do not modify `src/lab8/`, `src/config/`, `src/data/`, `src/tests/`, `src/reports/`, or `src/traces/`.
- `demo/data.js` sets exactly one global: `window.DEMO_DATA = { ... };`.
- Leak guard scans every string value in the bundle for `CANARY_SECRET_`, `CANARY_INTERNAL_`, `parent_secret`, `raw_headers`, `Authorization`, `Bearer `, and `\b0\d{9}\b`; on a hit, abort with no write.
- Generator must fail non-zero, without writing, when `src/traces/` is absent or a benchmark trial has no trace file.
- Report artifact must open from `file://`; never use `fetch` or module imports.
- Light theme, English UI labels, Vietnamese ticket text verbatim.
- Status is the only measured pass criterion; expected refund is labelled "expected, not measured".
- No colour-only meaning: every node and chip also has text.
- Commit after every task.

## Review Focus

- Fresh clone has no `src/traces/`: page must still open and the generator must refuse with the benchmark command.
- A zero-quote run (`C-002`): diagram must show `quote` and the amount branch as visited, `host check` and `ledger` unvisited.
- Cap cases (`C-008`, `C-014`): quote and expected refund differ; UI must label the expected value and not call it measured.
- Escalated run naming another principal's order (`C-005`): event detail shows only `order_id` and reason; no PII.
- Swarm seed 55 on `C-007` (or any `model_override` trace): override node lights, and the note ties it to seed divisible by 5.

## File Structure

- `tools/build_demo_ui.py` — load, sanitize, derive visited nodes, guard, write `demo/data.js`.
- `tools/tests/test_build_demo_ui.py` — generator tests.
- `demo/index.html` — page shell and containers.
- `demo/styles.css` — layout, tokens, diagram states, responsive and print rules.
- `demo/app.js` — graph coordinates, state, rendering.
- `demo/data.js` — generated, committed.
- `demo/README.md` — open/regenerate instructions and data limits.

### Task 2: Visited-node inference per shape

**Files:**
- Modify: `tools/build_demo_ui.py`
- Test: `tools/tests/test_build_demo_ui.py`

**Interfaces:**
- Produces:
  - `NODE_IDS: dict[str, list[str]]` mapping shape id to ordered node ids.
  - `visited_nodes(shape: str, status: str, events: list[dict]) -> list[str]`
  - Each bundle trace gains `visited: list[str]` and `quote_vnd: int | None`.

Node ids, in order:

```
workflow:     claim order_id lookup_order visible quote amount_positive host_check ledger outcome
single:       claim react ready quote amount_positive host_check ledger outcome
orchestrator: claim order_id handoff investigator visible quote amount_positive host_check ledger outcome
swarm:        claim peer_parse order_id handoff investigator model_override quote amount_positive host_check ledger outcome
```

def test_workflow_resolved_lights_host_and_ledger():
    events = [{"kind": "lookup_order", "payload": {"visible": True}},
              {"kind": "quote", "payload": {"amount_vnd": 35000}}]
    got = visited_nodes("workflow", "resolved", events)
    assert got == ["claim", "order_id", "lookup_order", "visible", "quote",

def test_workflow_zero_quote_skips_host_and_ledger():

              {"kind": "quote", "payload": {"amount_vnd": 0}}]
    got = visited_nodes("workflow", "denied", events)
    assert "host_check" not in got and "ledger" not in got
    assert got[-1] == "outcome"

def test_needs_info_visits_order_branch():
    got = visited_nodes("workflow", "needs_info", [{"kind": "decision", "payload": {"status": "needs_info"}}])
    assert got == ["claim", "order_id", "outcome"]

def test_escalated_visits_order_and_outcome():

- [ ] **Step 3: Implement `visited_nodes`**

Rules, applied in this order and returned in `NODE_IDS[shape]` order:

1. `claim` and `outcome` always.
2. `decision` event → `order_id`; stop after `outcome` if status is `needs_info`.
3. `lookup_order`, `react`, `handoff`, `investigator`, `model_override` add their own node; `lookup_order`, `handoff`, and `react` also add `order_id` where that id exists.
4. `lookup_order` event, or `investigator` event, adds `visible`.
5. `visible == False` with status `escalated` stops after `visible`/`outcome`.
6. `react` adds `ready`; status not `resolved` and no `quote` event stops after `ready`/`outcome`.
7. `quote` adds `quote` and `amount_positive`; `amount_vnd > 0` adds `host_check`.
8. Status `resolved` adds `host_check` and `ledger`; status `denied`/`failed` adds `host_check` only when a positive quote exists.
9. Shape `swarm` always adds `peer_parse`.
10. Unknown shapes raise `SystemExit`.

Set `trace["quote_vnd"]` from the last `quote` event or `None`, then `trace["visited"] = visited_nodes(shape, status, events)`.

### Task 4: Four pipeline diagrams with run highlighting

**Files:**
- Modify: `demo/app.js`, `demo/styles.css`, `demo/index.html`

**Interfaces:**
- Consumes: `trace.visited`, `NODE_IDS` ids (workflow ids above).
- Produces: `renderDiagram(shapeId, trace, status)` drawing `<g class="node" data-node-id="...">` inside SVG; `renderSteps(trace)` listing every event with mapped node id; `showEvent(index)` filling `#event-detail`.

- [ ] **Step 1: Write the shape graph constants**

Each node: `{id, x, y, w, h, type, label}` where `type` is one of `code`, `model`, `branch`, `host`, `ledger`, `terminal`. Layout each shape on a 980×320 viewBox; branch nodes are diamonds sized 120×70; labels are short (`claim`, `order?`, `lookup`, `visible?`, `quote`, `>0?`, `host check`, `ledger`, `outcome`). Edges are orthogonal line segments with arrow markers. Include the swarm `peer`, `handoff`, `investigator`, `override?` nodes.

- [ ] **Step 2: Render nodes and states**

For every node emit a `<g>` with class `node state-visited|state-unvisited type-{type} result-{status}`. Terminal node class is `result-{status}` only when visited. Add `<title>` for tooltips. Append a text state under the diagram: `visited N of M nodes · status {status}`. Draw a legend for code/model/branch/host/ledger and the three result colours.

- [ ] **Step 3: Step list and event detail**

`renderSteps` lists every trace event in order as `01 lookup_order · node: lookup` buttons. Clicking sets `aria-current`, highlights the mapped node with `is-active`, and prints pretty JSON in `#event-detail` plus `state inferred from run status` when the node has no event. Node click selects the first event mapped to it; if none, the detail panel says why.
